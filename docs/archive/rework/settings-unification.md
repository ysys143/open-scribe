# settings.json 통합 및 인증 경계 수정

> 역사 기록 — settings 통합 당시의 305개 검사·인증 이행·설치 결과다. 아래 `현재`·`완료`와 설치 경로·DB 표본은 그 작업 시점에 한정되며 이번 문서 정리에서 개인 설정이나 설치본을 다시 확인한 것이 아니다. 본문 증거는 보존했다. 현재 설정은 [사용 안내](../../user-guide.md), 구조·기능·옛 기록의 구분은 [문서 입구](README.md), 최신 코드 검사는 [통합 기록](../../development/optional-modes-implementation.md), 릴리스 진행은 [담당 F 기록](optional-modes-release.md)을 따른다.

사용자 제어면은 `~/.config/open-scribe/settings.json` 하나다. 원격·로컬 단계, 모델, 기능 활성화, 자원, 출력, 다운로드, Telegram·Notion 설정을 공통 로더에서 읽는다. CLI의 명시적 옵션만 파일보다 우선한다. 설정이 없을 때의 진단과 조회는 파일이나 DB를 만들지 않는다.

앱과 launcher의 개인 키 파일 탐색·source·키 로딩 재실행을 제거했다. `.env`도 자동으로 읽지 않는다. 인증은 설정에 적힌 환경변수 이름으로만 해석하며 키 값을 설정·작업·출력에 저장하지 않는다. 자격 증명 원본과 기존 `.env`는 수정하지 않았다.

## 실행과 상태

- 작업에 선택 모델·단계별 옵션·정책과 환경변수 참조를 동결한다. 현재 설정이 바뀌어도 재개는 작업의 기록을 따른다.
- 과거 스냅샷 없는 작업은 기록된 평면 필드로만 재구성한다. 기록되지 않은 Notion 대상을 현재 설정에서 가져와 게시하지 않는다.
- `helpers.json`은 실행에서 읽지 않는다. `doctor --qualify`는 별도 실측 증거만 저장하고 설정은 수정하지 않는다. 모델·런타임·기기·정책·길이가 증거와 맞아야 실행한다.
- 로컬 자원 정책은 부모·자식·watchdog·CPU thread 설정에 전달한다. helper 실패 시 원격 결과를 보존한다.

## 독립 검토에서 재현하고 수정한 항목

1. 비정상 usage 타입을 미확정 과금으로 보존해 유료 재호출을 차단했다.
2. 로컬 ASR 이행 시 선택 alias를 함께 가져온다.
3. null·배열·boolean·숫자·문자열 JSON 루트는 기본 설정으로 대체하지 않고 거부한다.
4. 활성 텍스트 모델은 실행기와 같은 기준으로 검증하고, 비활성 단계가 ASR을 막지 않는다.
5. 현재 키 참조가 바뀌어도 재개는 작업의 고정 참조를 사용한다. 키가 없으면 대기 상태를 보존한다.
6. 재개에서 생성한 HTTP client의 소유권을 보존해 종료 시 실제 client를 닫는다.

기존 출력 보존·리스·불확실 과금 보호 회귀를 유지했다. 임시 복사본의 기존 승인 기준 10개 결함 주입은 모두 검출했고, 명시적 false 설정을 무시하는 별도 변이도 검출했다. 실제 프로세스·SQLite·ffmpeg 경로를 실행했으며 HTTP와 ML 추론은 대역으로 구분했다.

초기 직접 API 검사에서 생성된 `test-asr` 테스트 출력 27개가 Downloads에 남은 것을 확인했다. 모델 표식으로 식별해 임시 보존 위치로 이동했고 삭제하지 않았다. 이후 전체 검사는 빈 임시 HOME/config/data에서 실행했다.

## 설치와 이행

기존 비밀 아닌 설정만 명시적으로 이행했다. retired 직접 공급자 설정과 기존 자격 플래그는 적용하지 않고 이름만 보고한다. 기존 설정·DB·음성 벡터·원본·이전 설치는 보존한다. 업그레이드는 후보 검사·활성 lease 확인·백업·교체 후 검사를 수행하며 실패 시 복구한다. 이동 가능한 venv와 이동 후 console 진입점도 검사한다.

실제 모델 다운로드·화자 품질/GPU 인증·Telegram/Notion 발송은 이번 설정 수정에서 수행하지 않는다. 실제 모델 관문은 여전히 미검증이다.

## 최종 검증 결과

- 빈 HOME/config/data에서 전체 **305개, 69.383초, OK**. 실행 전후 소스·테스트·설치기 해시가 일치했다. 로그: `/tmp/scribe-settings-final-verified.log`.
- 독립 검토 W4-01~06은 모두 해결 확인을 받았다. 실제 모델 품질/GPU 자격으로 확대하지 않는다.
- 로컬 설치 교체 완료. 이전 런타임은 `~/.local/lib/open-scribe.backup-ReOhTy`, 이전 명령은 `~/.local/bin/scribe.backup-ReOhTy`에 보존했다.
- 설치본 Python 소스 51개가 저장소와 같았다. 설치 명령의 config validate·doctor와 이동된 yt-dlp 진입점도 통과했다.
- 설치된 CLI에서 임시 설정 하나로 전사·SQLite 저장·TXT/JSON/SRT/VTT 출력과 원본 보존을 확인했다. HTTP만 MockTransport로 대체했고 실제 유료 API 호출은 0회다.
- 업그레이드 전후 기존 DB 행 수가 동일했다: historic 74, core jobs 74, people 0, embeddings 0. 설정 파일도 업그레이드 중 바뀌지 않았다.
- 활성 저장소·설치본에서 개인 키 경로와 키 로딩 재실행 참조가 없음을 검색했다. rollback용 이전 런타임은 과거 상태로 보존했다.

현재 실행은 `~/.config/open-scribe/settings.json`을 사용한다. 인증 환경변수가 전달되지 않으면 원격 처리는 변수 이름을 안내하고 중단한다. 앱이 개인 파일에서 키를 보충하지 않는다. `scribe config show`와 `scribe config validate`로 적용 설정을 확인할 수 있다.
